# Заметки для будущей документации (Этап 7)

Решения и договорённости по ходу разработки, которые нужно учесть при
написании финального README и упаковке проекта под портфолио.

## Версии моделей провайдеров могут устаревать

Google (и, вероятно, другие провайдеры) периодически снимают старые версии
моделей с поддержки — например, `gemini-2.5-flash` перестал быть доступен
для новых пользователей в августе 2026, пришлось вручную обновить `.env`
на `gemini-3.6-flash`.

Ключ API при этом не протухает — устаревает только имя модели в `.env`.

Что учесть в README:
- Явно предупредить, что имена моделей в `.env.example` могут устареть
  к моменту, когда кто-то клонирует репозиторий.
- Указать, где проверять актуальные модели:
  - Groq: https://console.groq.com/docs/models
  - OpenRouter: https://openrouter.ai/models (фильтр `:free`)
  - Gemini: https://ai.google.dev/gemini-api/docs/models
- Рассмотреть использование алиасов вроде `gemini-flash-latest` (если
  Google их предоставляет) вместо конкретных версионных имён — чтобы не
  нужно было вручную обновлять `.env` при каждом релизе. Проверить перед
  написанием README, существует ли такой алиас на тот момент.
- Признак, что модель устарела: в логах `LLM FAIL ... reason=HTTP 404`
  для конкретного провайдера — цепочка fallback подхватит следующего
  провайдера автоматически, но лучше объяснить пользователю, как чинить
  первопричину, а не полагаться на fallback постоянно.

## Язык интерфейса

2. **Язык интерфейса** — решение изменено в ходе Этапа 5: интерфейс
   PySide6 поддерживает переключение между русским, английским и
   испанским через выпадающий список в самом окне. Ответы агента также
   подстраиваются под язык, на котором задан вопрос (независимо от
   выбранного языка UI). Код и README на GitHub — по-прежнему
   английский (стандарт для портфолио) — это отдельный слой, не
   связанный с языком работающего приложения.
